What an AI agent is

More than a chatbot. Less than a magic employee.

A traditional chatbot follows a script: if the customer says X, reply Y. An AI agent uses a language model to understand a request in plain words, decide which steps are needed, use tools you have allowed (such as searching your product list, checking an order or creating a booking) and report back.

That makes agents useful for work that is repetitive but not perfectly predictable: a customer asking three questions in one message, an email that needs classifying and routing, or a sales enquiry that needs qualifying before a person gets involved.

Agents also make mistakes. Good agent design is mostly about limits: what the agent can see, which actions it may take, when it must ask a person, and how every step is recorded. That is where most of our engineering effort goes. Read more in AI agents vs traditional chatbots.

How we build agents

Guardrails are
the product.

The parts that make an agent safe to rely on are designed in from the start, not added after the demo.

A

Reasoning and grounding

The agent answers from your information, not from guesswork.

  • Retrieval from your documents and data
  • Model choice matched to the task and budget
  • Clear instructions and tested prompts
  • Evaluation sets built from real cases

B

Tools and permissions

Every action the agent can take is explicit and limited.

  • Least-privilege access to each system
  • Approval steps for sensitive actions
  • Rate limits and spending limits
  • Defences against prompt injection

C

Oversight and handover

People stay in charge of the outcome.

  • Handover to a person with full context
  • Logs of every conversation and action
  • Dashboards for review and correction
  • Regular tuning from real conversations

How an engagement works

Small first version.
Evidence before scale.

We would rather automate one workflow that works every day than ten that look good in a demo. Each stage ends with something you can see and decide on.

  1. 01

    Discovery call

    A short conversation about the work as it happens today: who does it, how often, which tools are involved and what a better outcome looks like.

  2. 02

    Map and prioritise

    We map the workflow, mark the steps worth automating and the ones that should stay human, and agree what “working” means in measurable terms.

  3. 03

    Build a focused first version

    One workflow, built around your existing tools, with logging, error handling and a clear way for a person to step in.

  4. 04

    Test with real cases

    We run it against real (or realistic) examples, including the awkward ones, and fix what breaks before anyone depends on it.

  5. 05

    Launch, measure, extend

    It goes live with your team, we watch the results together, and the evidence decides what we automate next.

Our own agents

We build agents into our own products first.

Huntly, our live AI job-search assistant, evaluates opportunities against a person’s profile and helps prepare applications. Staff, our AI employee platform, is in validation, with Maya, an AI receptionist, as its example employee.

Because AI agents can be steered by untrusted input, we also review agent security as a service: see Application & Cloud Security Review.

Agents are not infallible. Any agent built on a language model can misread a request. We design for that with limited permissions, confirmation steps and human handover, and we’ll recommend against an agent where a mistake would be costly and a simpler system would do.

Frequently asked questions

Questions, answered plainly.

What is the difference between an AI agent and a chatbot?

A scripted chatbot follows a fixed decision tree. An AI agent understands free-form requests and can take actions you allow, such as checking an order or creating a booking. Agents are more flexible, and need more careful limits.

Which AI models do you use?

We choose per task, from established providers, weighing quality, speed, cost and where data is processed. Agents are built so the model can be changed later without rebuilding everything.

Can an agent work on WhatsApp?

Yes, through the WhatsApp Business Platform, subject to Meta’s policies on opt-in, message templates and business verification. See WhatsApp automation.

How do you stop an agent doing something it shouldn’t?

It only gets the permissions the workflow needs, sensitive actions need confirmation, every action is logged, and inputs from customers or documents are treated as untrusted. We test these limits before launch.

Can you connect an agent to our existing systems?

Usually, if the system offers an API or another reliable way to connect. We check this in discovery, and if a system can’t be connected safely we’ll say so.

Do you build AI employees?

Staff, our AI employee platform, is still being validated. For client work we build focused agents for specific workflows, which is the honest way to start.
